# 1.08 Regularization Fundamentals

## Introduction

Chapter 1.6 showed that flexible models can overfit, and Chapter 1.7 showed that overfitting corresponds to high variance. **Regularization** is the family of techniques that reduce variance by deliberately limiting how freely a model can fit the training data. Goodfellow, Bengio, and Courville define it broadly as any modification to a learning algorithm intended to reduce its generalization error but not its training error [1].

The most common form adds a penalty on the size of the model's parameters to the loss. This chapter explains the two classic penalties, L2 (ridge) and L1 (lasso), their combination (elastic net), their probabilistic interpretation, and a few non-penalty techniques such as early stopping. Applying regularization to specific algorithms such as linear and logistic regression is covered in later chapters.

## Learning Objectives

- Interpret L1 and L2 penalties as Bayesian priors.
- Name other regularization techniques and when they are used.

## Fundamental Concepts

### The Basic Idea

An unregularized model chooses parameters that minimize the training loss alone. A regularized model minimizes the training loss **plus a penalty** that grows with model complexity. The penalty discourages extreme parameter values, which typically correspond to wildly varying, overfit functions [1], [2].

The penalty is scaled by a hyperparameter, usually written $\lambda$ (or $\alpha$ in scikit-learn). A larger value means stronger regularization: lower variance but higher bias. At $\lambda=0$ the model is unregularized; as $\lambda\to\infty$ the parameters are forced toward zero and the model underfits.

### L2 Regularization (Ridge)

Ridge regression penalizes the sum of squared coefficients. It shrinks all coefficients toward zero, but rarely to exactly zero, and it handles correlated features gracefully by spreading weight across them. It was introduced by Hoerl and Kennard to stabilize regression with nearly collinear predictors [3].

### L1 Regularization (Lasso)

Lasso penalizes the sum of absolute coefficient values. Its geometry causes some coefficients to be set exactly to zero, so it performs automatic **feature selection** and produces sparse, interpretable models [4].

### Elastic Net

Elastic net combines both penalties. It keeps the sparsity of L1 while retaining the stability of L2, which is useful when features are correlated: lasso alone tends to pick one feature from a correlated group arbitrarily [2].

| Property | Ridge (L2) | Lasso (L1) | Elastic net |
|----------|-----------|------------|-------------|
| Penalty | $\sum w_j^2$ | $\sum \lvert w_j\rvert$ | Weighted mix of both |
| Coefficients set exactly to 0? | Rarely | Yes | Yes |
| Feature selection | No | Yes | Yes |
| Correlated features | Shares weight among them | Tends to pick one | Shares weight and selects |
| Closed-form solution | Yes | No | No |
| Needs feature scaling | Yes | Yes | Yes |

### Probabilistic Interpretation

Regularization can be viewed as Bayesian prior knowledge. An L2 penalty corresponds to a Gaussian prior on the weights centered at zero ("weights are probably small"), and an L1 penalty corresponds to a Laplace prior, which is sharply peaked at zero ("many weights are probably exactly zero") [1].

### Other Regularization Techniques

| Technique | Idea |
|-----------|------|
| Early stopping | Stop iterative training when validation error stops improving [1] |
| Data augmentation | Create modified copies of training data to enlarge the effective dataset [1] |
| Dropout (neural networks) | Randomly disable units during training so the network cannot rely on any single one [1] |
| Limiting model size | Restrict tree depth, number of features, or polynomial degree |

## Mathematical Foundations

Let $J_{\text{data}}(\mathbf{w})$ be the training loss, for example the mean squared error, where $\mathbf{w}\in\mathbb{R}^m$ are the model weights. The regularized objectives are:

**Ridge (L2):**

$$
J_{\text{ridge}}(\mathbf{w}) = \frac{1}{n}\sum_{i=1}^{n}\bigl(y_i-\mathbf{w}^{\top}\mathbf{x}_i\bigr)^2 + \lambda\,\lVert\mathbf{w}\rVert_2^2, \qquad \lVert\mathbf{w}\rVert_2^2=\sum_{j=1}^{m}w_j^2
$$

**Lasso (L1):**

$$
J_{\text{lasso}}(\mathbf{w}) = \frac{1}{n}\sum_{i=1}^{n}\bigl(y_i-\mathbf{w}^{\top}\mathbf{x}_i\bigr)^2 + \lambda\,\lVert\mathbf{w}\rVert_1, \qquad \lVert\mathbf{w}\rVert_1=\sum_{j=1}^{m}\lvert w_j\rvert
$$

**Elastic net:**

$$
J_{\text{EN}}(\mathbf{w}) = \frac{1}{n}\sum_{i=1}^{n}\bigl(y_i-\mathbf{w}^{\top}\mathbf{x}_i\bigr)^2 + \lambda\Bigl(\rho\,\lVert\mathbf{w}\rVert_1 + (1-\rho)\,\lVert\mathbf{w}\rVert_2^2\Bigr)
$$

In these formulas, $n$ is the number of examples, $\mathbf{x}_i$ and $y_i$ are the features and target of example $i$, $\lambda\ge 0$ sets the regularization strength, and $\rho\in[0,1]$ mixes the two penalties. The intercept is normally not penalized. Libraries scale these terms differently (scikit-learn, for example, uses its own constant factors and calls $\lambda$ `alpha`), so the same numeric value is not interchangeable across libraries [2].

**Closed form for ridge.** Writing the data as a matrix $X\in\mathbb{R}^{n\times m}$ and the targets as $\mathbf{y}$, the minimizer of the sum-of-squares form $\lVert\mathbf{y}-X\mathbf{w}\rVert_2^2+\lambda\lVert\mathbf{w}\rVert_2^2$ (without the $1/n$ factor) is

$$
\hat{\mathbf{w}}_{\text{ridge}} = \bigl(X^{\top}X + \lambda I\bigr)^{-1}X^{\top}\mathbf{y}
$$

where $I$ is the identity matrix. Adding $\lambda I$ makes $X^{\top}X+\lambda I$ invertible even when features are perfectly correlated, which explains ridge's numerical stability [3].

**Why L1 gives zeros.** The L2 penalty's gradient, $2\lambda w_j$, shrinks toward zero as $w_j$ approaches zero, so it never reaches exactly zero. The L1 penalty has a constant-magnitude push, $\lambda\,\mathrm{sign}(w_j)$, toward zero regardless of how small the weight is, so weights can be driven to exactly zero. Geometrically, the L1 constraint region $\sum|w_j|\le t$ has corners on the axes, where the loss contours tend to touch it [4].

**Bayesian view.** If the data noise is Gaussian and the prior on each weight is $w_j\sim\mathcal{N}(0,\tau^2)$, the maximum a posteriori estimate minimizes the ridge objective, with $\lambda$ determined by the ratio of noise variance to prior variance. With a Laplace prior $p(w_j)\propto e^{-\lvert w_j\rvert/b}$ it minimizes the lasso objective [1].

## Advantages and Limitations

| Advantages | Limitations |
|------------|-------------|
| Reduces variance and overfitting | Introduces bias; too much regularization underfits |
| Stabilizes models with correlated or numerous features | Requires tuning the strength $\lambda$ |
| Lasso gives sparse, interpretable models | Lasso can be unstable among highly correlated features |
| Cheap to add to many algorithms | Penalties depend on feature scale, so scaling is required |
| Ridge has a closed-form solution | Penalized coefficients are biased and less suitable for causal interpretation |

## Common Mistakes

- **Not scaling features.** A feature measured in large units has small coefficients and is penalized less, which distorts the effect.
- **Penalizing the intercept.** The intercept should usually be left out of the penalty.
- **Choosing $\lambda$ on the test set.** Select it by cross-validation on training data.
- **Expecting ridge to select features.** Ridge shrinks but rarely zeroes coefficients.
- **Interpreting lasso's selected features as the only important ones.** With correlated features, which one is chosen can be arbitrary and change between samples.
- **Comparing alpha values across libraries.** Conventions for scaling the loss and penalty differ.

## Chapter Summary

- Regularization limits model flexibility to reduce variance and improve generalization.
- Ridge (L2) shrinks coefficients smoothly; lasso (L1) drives some exactly to zero; elastic net blends both.
- The strength $\lambda$ controls the bias-variance balance and should be chosen by cross-validation.
- L2 and L1 penalties correspond to Gaussian and Laplace priors on the weights.
- Early stopping, data augmentation, dropout, and limiting model size are other regularization strategies.
- Features must be scaled before applying penalties.
