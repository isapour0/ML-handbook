# 1.3 Data Preprocessing and Feature Engineering

## Introduction

Raw data is rarely ready for a learning algorithm. It may contain missing values, categories stored as text, features on wildly different scales, and attributes that are redundant or irrelevant. **Data preprocessing** converts raw data into a clean numeric form, and **feature engineering** creates or selects representations that make the underlying pattern easier to learn.

Practitioners often report that these steps influence results more than the choice of algorithm. Domingos observes that feature engineering is frequently the key factor separating successful projects from failed ones, because learning is easy once the right features exist [1]. This chapter covers the standard tools for handling missing data, scaling, encoding, transforming, and selecting features. How to apply them without contaminating evaluation is the subject of Chapter 1.13.

## Learning Objectives

After studying this chapter you should be able to:

- Identify common data quality problems and choose a suitable treatment.
- Impute missing values and explain when each strategy is appropriate.
- Apply standardization, min-max scaling, and robust scaling, and say which algorithms need them.
- Encode categorical variables using one-hot and ordinal encoding.
- Create new features and apply transformations to skewed data.
- Build a reproducible preprocessing step for mixed numeric and categorical columns.

## Fundamental Concepts

### Types of Features

| Feature type | Description | Example | Typical treatment |
|--------------|-------------|---------|-------------------|
| Numerical continuous | Real-valued measurement | Height, price | Scaling, transformation |
| Numerical discrete | Counts | Number of rooms | Often used as is |
| Nominal categorical | Categories with no order | Color, city | One-hot encoding |
| Ordinal categorical | Ordered categories | Small, medium, large | Ordinal encoding |
| Text, date, image | Unstructured or composite | Review text, timestamp | Extract numeric features |

### Handling Missing Values

Values can be missing for different reasons: at random, depending on other observed variables, or depending on the missing value itself. The reason affects which treatment is safe [2].

- **Deletion** removes rows or columns with missing entries. It is simple but wastes data and can bias results when missingness is not random.
- **Simple imputation** replaces a missing value by the mean, median, most frequent value, or a constant. The median is more robust to outliers than the mean.
- **Model-based imputation** predicts missing values from other features, for example with nearest neighbors or iterative regression.
- **Missing indicators** add a binary column recording whether the value was missing, which preserves the information that something was absent [4].

### Feature Scaling

Many algorithms compare distances or follow gradients, so features with large numeric ranges can dominate. Scaling puts features on comparable ranges. Algorithms based on distances (k-nearest neighbors, SVM, k-means), on gradient descent (linear and logistic regression, neural networks), and on penalized coefficients (ridge, lasso) generally benefit. Tree-based models are largely insensitive to monotonic rescaling [3].

| Method | Formula | Result | Sensitive to outliers? |
|--------|---------|--------|------------------------|
| Standardization | $(x-\mu)/\sigma$ | Mean 0, standard deviation 1 | Yes |
| Min-max scaling | $(x-x_{\min})/(x_{\max}-x_{\min})$ | Range $[0, 1]$ | Very |
| Robust scaling | $(x-\text{median})/\text{IQR}$ | Median 0, spread by IQR | Less |

### Encoding Categorical Variables

Algorithms need numbers, but converting categories to integers arbitrarily creates a false order. **One-hot encoding** creates one binary column per category and is the default for nominal variables. **Ordinal encoding** maps ordered categories to integers that respect their order. High-cardinality variables (such as postal codes with thousands of values) may need grouping or target-based encodings, which must be used carefully to avoid leakage [2], [3].

### Feature Creation and Transformation

New features can express domain knowledge or relationships the raw columns hide: ratios (price per square meter), differences, aggregates, interaction terms ($x_1 x_2$), polynomial terms, and components extracted from dates (day of week, month) [2]. Skewed positive variables such as income often become easier to model after a logarithmic transformation.

### Feature Selection

Removing irrelevant or redundant features can reduce overfitting, speed training, and aid interpretation. Approaches include **filter** methods (rank features by a statistic such as correlation), **wrapper** methods (search feature subsets using model performance), and **embedded** methods (the model selects features during training, as lasso does) [2].

## Mathematical Foundations

**Standardization** (z-score):

$$
z = \frac{x - \mu}{\sigma}
$$

where $x$ is the original value, $\mu$ is the feature's mean, and $\sigma$ its standard deviation, both computed from the training data. After the transformation the feature has mean 0 and variance 1; $z$ expresses how many standard deviations a value lies from the mean.

**Min-max scaling**:

$$
x' = \frac{x - x_{\min}}{x_{\max} - x_{\min}}
$$

where $x_{\min}$ and $x_{\max}$ are the smallest and largest training values. The result lies in $[0,1]$ for training data; new values outside the training range can fall outside it.

**Robust scaling**:

$$
x' = \frac{x - Q_2}{Q_3 - Q_1}
$$

where $Q_1, Q_2, Q_3$ are the 25th, 50th, and 75th percentiles. The denominator, the interquartile range (IQR), ignores the extremes, so outliers distort the scale much less.

**One-hot encoding** maps a category $c\in\{1,\dots,K\}$ to a vector $\mathbf{e}_c\in\{0,1\}^K$ with a single 1 at position $c$. With an intercept in a linear model, one column is redundant, because the columns sum to one; dropping one avoids perfect collinearity.

**Log transform** for a positive skewed feature: $x' = \log(1+x)$, where adding 1 keeps the transform defined at $x=0$.

## Practical Applications

The example below builds a preprocessing step for a small table with numeric and categorical columns, including missing values. Each column group gets its own treatment, and the result is a purely numeric matrix.

```python
import numpy as np
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler, OneHotEncoder

df = pd.DataFrame({
    "area":   [50, 70, np.nan, 120, 150],
    "age":    [30, 20, 15, np.nan, 5],
    "city":   ["A", "B", "A", "C", np.nan],
})

numeric = make_pipeline(SimpleImputer(strategy="median"), StandardScaler())
categorical = make_pipeline(
    SimpleImputer(strategy="most_frequent"),
    OneHotEncoder(handle_unknown="ignore"),
)

prep = ColumnTransformer([
    ("num", numeric, ["area", "age"]),
    ("cat", categorical, ["city"]),
])

X = prep.fit_transform(df)
print(X.shape)
print(prep.get_feature_names_out())
```

Typical applications: cleaning customer records before churn prediction, scaling sensor measurements before clustering, and encoding product categories for demand models.

## Advantages and Limitations

| Advantages | Limitations |
|------------|-------------|
| Often improves accuracy more than changing the algorithm | Requires domain knowledge and experimentation |
| Makes algorithms that rely on distances or gradients work properly | Poor choices can discard information or add noise |
| Handles real-world messiness such as missing values | Imputation can hide patterns or introduce bias |
| Improves interpretability when features are meaningful | One-hot encoding of high-cardinality columns creates huge matrices |
| Enables the same pipeline to be reused on new data | Hand-crafted features may not transfer to other problems |

## Common Mistakes

- **Fitting the scaler or imputer on all the data.** Statistics such as $\mu$ and $\sigma$ must be learned from the training set only; otherwise information from the test set leaks into training (see Chapter 1.13).
- **Encoding nominal categories as integers.** A model may treat city 3 as "larger" than city 1.
- **Dropping rows with missing values by default.** This can remove a large share of the data or bias the sample.
- **Scaling tree-based models unnecessarily** or forgetting to scale distance-based ones.
- **Applying min-max scaling to data with outliers.** A single extreme value can squash all other values into a tiny range.
- **Forgetting the dummy-variable trap** in unregularized linear models.

## Chapter Summary

- Preprocessing turns raw data into numeric matrices a learning algorithm can use; feature engineering improves the representation itself.
- Missing values can be removed, imputed with simple or model-based methods, or flagged with indicators.
- Scaling matters for distance-based, gradient-based, and penalized models; robust scaling is safer with outliers.
- Nominal categories need one-hot encoding; ordered categories can use ordinal encoding.
- New features and transformations (ratios, interactions, logarithms) often add more value than a different algorithm.
- All statistics used in preprocessing must be learned from training data only.
